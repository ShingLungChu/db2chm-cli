# 0.2.0-beta.1 发布决定与范围

2026-10-27，用户在获知未完成项后明确要求“请同步代码至github后进行发布”。本次按既定预发布顺序发布个人 scope `@jackiechen1994` 的 beta；这不是 stable/latest 放行。

## beta 必须实际通过的检查

- 五个包的版本、命名、依赖、native/JAR 哈希和源码提交可追溯，不能把私有原型直接改名发布。
- 发布的 native 可执行代码与四平台已验收基线逐字节相同；共享业务 JAR 也保持一致。
- 独立 native 的完整工具源码、原始版权、LGPL/FPC/FastHTMLParser 许可、修改日期、实际重建脚本和运行库来源同包交付。日期注释与原编译源码逐 SHA 映射；Windows 从交付源码真实重建并与原 native 哈希相同。
- 四个平台实际安装候选入口及本平台依赖，生成 CHM；Windows 解包四份文档并对比正文文件；最终压缩下载链严格小于 15,000,000 字节。
- Oracle、达梦（及额外 Vastbase）功能证据与相同的业务/native 字节绑定，中文文档人工验收通过。发布后再从真实 npm registry 做四平台安装/导出验证。

## 明确保留的限制

`release/beta-policy.json` 只对这个明确版本及 beta 标签允许以下有限状态；发布校验不会将它们改写为完全 passed，也不能将这些状态用于 stable：

| 项目 | beta 状态 | 对外声明 |
| --- | --- | --- |
| 更老操作系统 | 未验证 | 按实际已测系统/运行时矩阵说明，不承诺二进制部署字段所暗示的全部旧系统 |
| 数据库账号权限、服务端 SQL 及前后审计 | 用户当前无证据，保持未验证 | 产品固定只读查询与输入拒绝已有测试，不能据此宣称账号没有写权限或服务端审计通过 |
| 每个未修改 FPC runtime 单元的完整源码重建与工具链完全固定 | 未完成 stable 强标准 | 按 FPC 的独立模块链接例外分发未修改运行库，明确来源；不冒充已经证明全部 runtime 精确同源或所有环境完全复现 |

G1 的第三方分发材料、G3 的安装/大小、G4 的功能、包内容与校验值始终为硬检查，不在例外内。[实际许可判断](native-beta-distribution-review.md)区分这些义务与原 stable 工程目标。

## 发布顺序和身份

四个平台包先发布，统一入口最后发布，使用 `beta` 标签；逐包核对 registry 的 SHA-512 integrity。初次发布可使用用户已登录的本机 npm 身份；本机发布不声称具有 CI provenance attestation。CI OIDC/trusted publisher 配置另行完成后才在该环境启用 `--provenance`。

若 npm 要求额外身份验证，由账号持有人完成浏览器/终端验证，不将密码、OTP 或令牌写入聊天、源码或报告。已发布版本不能替换内容；发生部分失败时只补发缺失的相同字节。`latest` 不在本次预发布操作范围。
